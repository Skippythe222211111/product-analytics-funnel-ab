# Протокол до просмотра результатов

## Популяция и единица анализа

Единица рандомизации и анализа — новый синтетический пользователь. На пару experiment_id + user_id допускается ровно одно назначение. Вариант назначается случайной перестановкой пользователей в равные группы с фиксированным seed. В анализе назначение остаётся в знаменателе независимо от наличия последующих событий.

## Воронка

Порядок зафиксирован заранее: landing_view → signup → activation → purchase. Для каждого пользователя учитывается самое раннее событие этапа, которое произошло после предыдущего этапа. Timestamp этапа должен быть строго больше timestamp предыдущего; дубликаты событий не увеличивают счётчик. Окно от assigned_at до assigned_at + 7 суток, включая обе границы. Событие после окна не засчитывается. Если пользователь не дошёл до этапа, он остаётся только в знаменателях предыдущих этапов и общего назначения; таблица показывает абсолютные количества этапов и назначений.

## Когорты и удержание

Когорта пользователя — календарная UTC-дата его первой валидной регистрации в последовательной воронке. D1 — не менее одного active в календарную дату cohort + 1 день. D7 — не менее одного active в дату cohort + 7 дней. Это календарные даты, не elapsed-time окна. Знаменатель каждого retention-показателя — уникальные зарегистрировавшиеся пользователи когорты. Для D7 включаются только когорты, где источник подтверждает полноту наблюдения до cohort + 7. Разрез по датам когорты сохраняется; суммарные доли в отчёте взвешены по числу пользователей.

## Предварительно заданный A/B-протокол

- **Основная метрика:** доля всех назначенных пользователей с первым валидным событием purchase не позднее 7 суток после назначения и строго после landing_view, signup и activation.
- **Окно атрибуции:** 7 суток после assigned_at, включительно. Основной знаменатель — все назначенные в соответствующую группу пользователи.
- **Назначение:** случайное равное распределение пользователей; назначение не меняется при повторном событии.
- **SRM:** χ²-проверка наблюдаемых размеров control/treatment против ожидаемого распределения 1:1; сигнал при p < 0,001. SRM-проверка предшествует интерпретации эффекта.
- **План выборки:** baseline 0,12; абсолютный MDE 0,024 (2,4 п.п., 20% относительного прироста к baseline); двусторонний α=0,05; мощность 0,80. Минимальный n/группу получен целочисленным поиском по нормальной аппроксимации мощности двух независимых долей с альтернативной стандартной ошибкой. Расчёт: 3 119; фиксированный размер симуляции округлён вверх до 3 200 на группу.
- **Тест:** двусторонний pooled z-тест разности независимых долей при α=0,05.
- **Интервал:** 95% интервал Ньюкомба (score/Wilson) для разности treatment − control.
- **Практическая важность:** оценка и интервал сравниваются с плановым MDE. Наличие p < 0,05 само по себе не означает, что эффект ценен; MDE здесь также не является универсальным порогом ценности.
- **Множественные проверки:** одна основная метрика и один двусторонний тест. Воронка и retention — описательные показатели, из них не выбирается дополнительная метрика после просмотра.

## Статус вывода

Генератор создаёт случайно назначенные группы и заданные вероятности событий, чтобы проверить аналитику на воспроизводимом примере. Результат каждого прогона — описание конкретной симуляции. Из него нельзя заключать о причинном эффекте изменения в реальном продукте, поведении реальных пользователей или переносимости результата.
