# Словарь данных

Все значения и результаты в проекте синтетические. Временные метки заданы в UTC. Один пользователь — единица рандомизации и анализа; ключ назначения — пара experiment_id + user_id.

## experiment_assignments.csv

| Поле | Тип | Значение |
|---|---|---|
| experiment_id | text | Идентификатор одного симулируемого эксперимента. |
| user_id | text | Синтетический стабильный идентификатор пользователя вида u0000001. |
| variant | text | Назначенная группа: control или treatment. Группа назначается ровно один раз на пользователя в эксперименте. |
| assigned_at | ISO 8601 UTC | Время назначения и начала окна атрибуции. |
| assigned_epoch_s | integer | Unix epoch timestamp в секундах UTC; используется для сравнения времён без неоднозначности часового пояса. |
| assigned_day_utc | integer | Целое число дней Unix UTC для даты назначения. |
| data_complete_through_day_utc | integer | Последний полностью наблюдаемый календарный день UTC. Используется для исключения незрелых D7-когорт. |

## events.csv

| Поле | Тип | Значение |
|---|---|---|
| event_id | text | Уникальный идентификатор события; activity D1 и D7 различаются суффиксом. |
| experiment_id | text | Идентификатор эксперимента; должен совпадать с назначением пользователя. |
| user_id | text | Синтетический пользователь, которому принадлежит событие. |
| event_name | text | landing_view, signup, activation, purchase или active. |
| event_ts | ISO 8601 UTC | Время события. |
| event_epoch_s | integer | Unix epoch timestamp в секундах UTC, производный от event_ts. |
| event_day_utc | integer | Целое число дней Unix UTC, производное от event_ts; используется для D1/D7. |

## Правила интерпретации

- Назначение — исходный знаменатель A/B и последовательной воронки. Оно не удаляется из знаменателя, если у пользователя нет последующего события.
- landing_view — первый этап воронки; синтетический генератор помещает его ровно во время назначения.
- active — событие для удержания; это не этап воронки.
- Отсутствие active трактуется как отсутствие активности только внутри полностью наблюдаемого периода.
- Поля epoch/day должны вычисляться при загрузке из соответствующей UTC-метки. В штатном генераторе они согласованы и проверяются.
- Таблицы содержат только симулированные записи; исходных персональных или внешних данных нет.
